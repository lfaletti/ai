🔤 Tokenización Específica para C#

💡 ¿Por qué un tokenizador especial? Un tokenizador genérico (como el de GPT) rompería => en = + >, perdiendo el significado del operador lambda. Nuestro tokenizador reconoce operadores compuestos, divide PascalCase, y preserva la estructura del código C#.

👁️ Attention Maps — ¿A qué presta atención el modelo?

💡 Interpretando Attention Maps: Cada celda muestra cuánta "atención" presta el token de la fila al token de la columna. Colores más intensos = más atención. En código C#, esperamos ver:
  • Atención fuerte de } hacia { (cerrando bloques)
  • Atención de variables hacia su tipo declarado
  • Atención de await hacia async

⚡ Generación Token por Token

💡 Cómo genera código el modelo: El Transformer genera UN token a la vez. En cada paso, calcula la probabilidad de TODOS los tokens posibles y elige uno (usando temperatura y top-k sampling). Haz clic en cada token generado para ver los candidatos alternativos.

🔍 Flujo RAG (Retrieval-Augmented Generation)

💡 ¿Qué es RAG? RAG permite al modelo CONSULTAR una base de código existente antes de generar. Es como cuando un programador revisa el código del proyecto antes de escribir algo nuevo. Esto mejora la consistencia y reduce las "alucinaciones" del modelo.

⚖️ Comparación: Generación Con vs Sin RAG

💡 ¿Cuándo RAG mejora la generación? RAG es más útil cuando:
  • El proyecto tiene patrones/convenciones específicas
  • Se necesita código coherente con el código existente
  • Se usan APIs o librerías específicas del proyecto
  • Se quiere reducir "alucinaciones" del modelo
